### ❗核心报错与根因
第 3 步「探测真实连接」报：
```
ImportError: no pq wrapper available.
Attempts made:
- couldn't import psycopg 'c' implementation: No module named 'psycopg_c'
- couldn't import psycopg 'binary' implementation: No module named 'psycopg_binary'
- couldn't import psycopg 'python' implementation: libpq library not found
```
根因：用户执行的是 `uv add psycopg`，pyproject 里是 `"psycopg>=3.3.6"`（**没有 `[binary]` extra**）。
venv 里只有纯 Python 的 `psycopg`，没有 `psycopg_binary` / `psycopg_c`。

**psycopg3 三个实现**（这是要记住的知识点）：
1. `psycopg_c` —— C 扩展，需要本地编译工具链
2. `psycopg_binary` —— 预编译轮子，**自带 libpq**（Windows 上唯一省事的选择）
3. 纯 Python 实现 —— 必须有系统级 libpq 动态库

Windows 机器基本不可能有 libpq.dll，所以三条路全断。

**修法**：`uv add "psycopg[binary]"`
（**引号必须有**：`[binary]` 在 bash 里是通配符语法，不加引号可能被 shell 展开。）

### ❗问题 1（"执行第 9 步没有输出"的根因）
`scripts/stage1_check.py` 第 64 行的**字面内容**是：
```
if __name__ == "__&#8203;main__":
```
即混进了 **8 个字符的 HTML 实体 `&#8203;`**（不是真正的 U+200B —— 我全项目扫描
零宽字符得 0 处，说明是字面 ASCII 的 `&#8203;`）。
→ `__name__` 永不等于 `"__&#8203;main__"`，所以 `if` 块从不执行，
脚本只定义函数就退出：**退出码 0、零输出、无任何报错**。

**来源：用户从我上一条聊天消息复制代码时带进来的 HTML 转义实体。**
→ **教训（已告知用户，以后我也要注意）**：给用户贴大段代码时，若内容里含
`__main__` 这类带下划线的名字，复制链路可能把内容转义。以后交付代码后应主动提醒
「粘完先看有没有混进 `&#` 或异常字符」，或给出自查命令
`grep -rn "&#" --include="*.py" .`。
→ 这类 bug 的阴险之处：**语法完全合法、ruff 也不报**，只有行为不对。

### ❗问题 2：ruff 报 7 个 RUF001/RUF002（我的配置选型问题）
`select = ["E","F","I","UP","B","SIM","RUF"]` 里的 `RUF` 带进了
`RUF001/002/003`（ambiguous-unicode-character），会把中文**全角标点**
（`，` `：` `！`）在字符串/文档字符串/注释里全部标红。

**修法（已告知用户）**：`[tool.ruff.lint]` 加
`ignore = ["RUF001", "RUF002", "RUF003"]`。
理由：中文注释与中文用户输出的全角标点是**正确用法**，不是错误；
对中文项目这是标准做法。代价是失去「误把半角打成全角」的提醒，可接受。
